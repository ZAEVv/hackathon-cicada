# Демо Smart Caspian Transit — 5 минут

Сценарий для синтетического demo-only MVP. Часы фиксированы: `2026-11-12T08:00:00Z`, seed 42. Расписания, координаты, погода и история — синтетические; это не заявление о реальных рейсах, наличии мест или таможенных правилах.

## Перед показом

```bash
./scripts/check.sh
./scripts/dev.sh backend8000 frontend5173
```

- UI: `http://localhost:5173`, проверка API: `http://localhost:8000/api/health`.
- Демо-токены: брокер `demo-broker-token`, ревьюер `demo-reviewer-token`. Это локальные demo-secrets, не production-доступ. Для мутаций введите broker-токен; reviewer-токен понадобится только на шаге review.
- Для чистого прогона используйте пустую SQLite (`DATABASE_PATH`), иначе старая декларация может быть уже в статусе `demo_accepted`.
- Если нужен только API — те же шаги проходят через REST; UI не является отдельным mock-бэкендом.

## Если что-то пошло не так

- `401` — не введён или неверен bearer-токен; роли определяются токеном, отдельного role-заголовка нет.
- `404` на validate/submit — декларации ещё нет; сначала Save.
- `409`/`422` — ожидаемая реакция на конфликт версии/идемпотентности или неверный ввод; это не «баг демо».
- Перезапуск API сбрасывает состояние симуляции, но декларации и аудит в SQLite сохраняются. Для повторного показа pre-clearance начните с чистой БД.
