# Демо Smart Caspian Transit — сценарий для жюри, 5–7 минут

Сценарий для синтетического demo-only прототипа. Часы фиксированы: `2026-11-12T08:00:00Z`, seed 42.
Расписания, координаты, погода и история — синтетические; это не заявление о реальных рейсах,
наличии мест или таможенных правилах. Значения ниже получены в текущей версии кода (проверены
через API); если на экране отличается — верьте экрану, а не этому файлу.

## Перед показом

```bash
docker compose down -v         # чистая БД: иначе старая декларация уже «Принята в демо»
docker compose up -d --build   # UI: http://127.0.0.1:5173
curl http://127.0.0.1:5173/api/health
```

Без Docker: `./scripts/dev.sh` (UI там же, `http://127.0.0.1:5173`; чистая БД — удалить
`smart_caspian_demo.sqlite3` или задать `DATABASE_PATH`). Проверка перед выходом: `./scripts/check.sh`
(на нагруженной машине с `OMP_NUM_THREADS=1`).

Токены ролей предзаполнены в окне «Доступ»: логист `demo-broker-token`, проверяющий
`demo-reviewer-token`. Это локальные demo-secrets. Интерфейс сам подставляет нужный токен для
каждого действия. Откройте вкладку в светлой или тёмной теме, окно шириной от 1280 px.

Адреса для быстрых переходов:

| Экран | Адрес |
|---|---|
| Обзор SCT-001 | `http://127.0.0.1:5173/#/overview/SCT-001` |
| Документы SCT-001 | `http://127.0.0.1:5173/#/documents/SCT-001` |
| Модель | `http://127.0.0.1:5173/#/model` |
| Сводка | `http://127.0.0.1:5173/#/minimal` |

## Если что-то пошло не так

- Белый экран или «Нет соединения с сервером» → «Повторить»; затем `docker compose ps` и
  `curl http://127.0.0.1:5173/api/health`; при необходимости `docker compose restart`. Состояние
  сценариев сбросится, декларации и аудит сохранены в томе.
- Слой «Загрузка узлов» не загрузился (карточка «Прогноз загрузки недоступен») → показать
  данные через «Сводку»/«Модель» и сказать, что прогноз узлов доступен в API
  `GET /api/hubs/forecast`; обновить страницу.
- `401` — токен не принят: окно «Доступ» (`demo-broker-token`, `demo-reviewer-token`), «Сохранить».
- Кнопки «Проверить»/«Отправить» неактивны → сначала «Сохранить черновик»: проверка работает по
  сохранённой версии, отправка — только из статуса «Готова к отправке».
- Декларация уже «Принята в демо» (повторный показ) → `docker compose down -v` и заново, либо
  показать другую перевозку, например SCT-002.
- `409`/`422` — ожидаемая реакция на конфликт версии или неверный ввод, не баг.
- Не сработала живая демонстрация целиком → запасной путь: `.venv/bin/python scripts/demo.py`
  против запущенного API, он проходит тот же сценарий с проверками и печатает результат.
