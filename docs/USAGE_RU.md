# Инструкция по использованию Smart Caspian Transit

Пошагово: как установить, запустить, пользоваться каждым экраном, управлять контейнерами и что делать при проблемах.

---

## 1. Что нужно заранее

| Что | Зачем | Как проверить |
|---|---|---|
| Docker Engine + Docker Compose v2 | Весь проект запускается в контейнерах | `docker compose version` |
| Git | Скачать репозиторий | `git --version` |
| ≈3 ГБ свободной памяти и ≈3 ГБ на диске | Neo4j (до 1,25 ГБ ОЗУ), приложение, образы | — |
| Свободный порт `5173` | На нём открывается сайт | `ss -ltn \| grep 5173` — пусто |
| Интернет (желательно) | Живая погода Open-Meteo и первая сборка образов | Без интернета сайт работает на резервной погоде |

**Linux:** чтобы запускать Docker без `sudo`, добавьте себя в группу `docker` и перелогиньтесь:

```bash
sudo usermod -aG docker $USER
```

## 2. Первый запуск

```bash
git clone https://github.com/ZAEVv/hackathon-cicada.git
```

```bash
cd hackathon-cicada
```

```bash
docker compose up -d --build
```

- Первая сборка занимает 2–5 минут: скачиваются образы Python, Node и Neo4j. Следующие запуски — секунды.
- Поднимается 5 контейнеров:

| Контейнер | Что это |
|---|---|
| `app` | Сайт и API |
| `graph` | Графовая база Neo4j |
| `witness-1` | Узел реестра «Таможня» |
| `witness-2` | Узел реестра «Порт» |
| `witness-3` | Узел реестра «Перевозчик» |

Проверьте, что все контейнеры поднялись. У каждого должен быть статус `healthy`, приложению нужно около 30–60 секунд:

```bash
docker compose ps
```

Откройте в браузере **http://127.0.0.1:5173**.

> Все команды `docker compose …` выполняются **из папки проекта**, где лежит `docker-compose.yml`. Иначе Docker ответит «no configuration file provided».

## 3. Работа с сайтом

Слева — панель разделов: **Обзор**, **Документы**, **Модель**, **Сводка**, **Доступ**.
Сверху справа — время симуляции и переключатель светлой и тёмной темы.

> Время симуляции заморожено на **12 ноября 2026, 08:00 UTC**, чтобы сценарии всегда давали одинаковый результат. Погода при этом настоящая, на текущий момент.

### 3.1. Обзор — цифровой двойник перевозок

Что на экране:

- **«Перевозки под риском»** — сколько из 6 перевозок рискуют сорвать стыковку. В базовом состоянии 3 из 6.
- **Список перевозок SCT-001…006:**
  - есть поиск («Поиск перевозки») и сортировка (по номеру, «Сначала под риском», по прогнозу прибытия);
  - нажмите на перевозку, чтобы открыть её двойник.
- **Карта Каспия:**
  - текущий маршрут и плечи (ж/д → паром → авто), положение груза;
  - кнопки над картой: «Альтернативы», «Подписи», «Загрузка узлов» включают и выключают слои;
  - «Приблизить», «Отдалить», «Показать весь маршрут» — зум. Также работает колесо мыши и двойной клик. При приближении карту можно двигать мышью.
- **Ползунок «Горизонт прогноза»** и кнопка **«Проиграть прогноз на 72 часа»** показывают загрузку узлов на час вперёд.
- **«Узкие места · 72 ч»** — по каким хабам и в какие часы ожидается перегрузка, и какие перевозки в неё попадут.
- **Карточка перевозки:**
  - прогноз прибытия, риск и его причины;
  - погода с источником (например «Погода: Open-Meteo, 13.11 03:15 UTC»);
  - CO₂е и стоимость;
  - альтернативные маршруты с кнопкой **«Выбрать»**.
- **Переключатель «Перевозки / Сводка»** над списком показывает короткую сводку по коридору.

Сценарии (блок **«Сценарий»**):

| Кнопка | Что моделирует | Что увидите на SCT-001 |
|---|---|---|
| **Базовый** | Текущие условия | Риск низкий |
| **Шторм** | Сильный ветер и волна у текущего порта перевозки | Стыковка сорвана, риск высокий, Махачкала перегружена до ≈165 % |
| **Очередь** | Дополнительная очередь в порту | Растёт задержка готовности |
| **Закрытие** | Основной паромный рейс недоступен | Предложен обход через Амирабад |
| **Сбросить** | Вернуть базовый сценарий | — |

Сценарии заменяют друг друга: одновременно действует только один.

**Выбор альтернативного маршрута:**

1. Включите «Закрытие».
2. В карточке перевозки найдите альтернативу «Махачкала → Амирабад → Тегеран».
3. Нажмите **«Выбрать»**.

Маршрут сменится на карте, в прогнозе загрузки узлов и в сводке. Выбор — это моделирование, не бронирование.

### 3.2. Документы — предварительное таможенное оформление

Откройте **Документы** и выберите перевозку в поле «Перевозка». Форма уже заполнена корректными данными:

- отправитель «ООО «Волга Экспорт»»;
- код ТН ВЭД 847990;
- инвойс, упаковочный лист и транспортный документ.

**Автоматическое принятие (основной путь):**

1. **«Сохранить черновик»** → появляется «Версия 1».
2. **«Проверить»** → «Готова к отправке». Документы сверены между собой.
3. **«Отправить»** → статус **«Принята»** автоматически.

В карточке **«Смарт-контракт оформления»** видно: набор правил `rules-v1`, его хэш и галочки по R1–R5.

**Проверка на ошибку:** в «Упаковочный лист» поменяйте «Масса, кг» (например, 19000). Затем «Сохранить черновик» → «Проверить» → «Есть замечания»: массы не совпадают. Верните исходное значение.

**Ручная проверка инспектором:**

1. Поменяйте «Отправитель» на любое другое имя.
2. «Сохранить черновик» → «Проверить» → «Отправить» → статус «На рассмотрении», не пройдено правило R4 (недоверенный отправитель).
3. В карточке **«Рассмотрение»** напишите комментарий (по желанию) и нажмите **«Принять»** или **«На доработку»**.

Это действие роли проверяющего. Брокер не может принять собственную декларацию: сервер ответит `403`.

**Журнал и реестр:**

- **«Журнал действий»** — все действия с декларацией, каждая запись сцеплена хэшем с предыдущей.
- **«Проверить цепочку»** → «Целостность подтверждена · записей: N».
- **Строка реестра** показывает, какие узлы подписали запись, например «Таможня · подписал», «Порт · подписал», «Перевозчик · подписал». Ниже итог: «3 из 3 узлов подписали · кворум 2 из 3 достигнут».

Правила смарт-контракта:

| Правило | Проверяет |
|---|---|
| R1 | Документы согласованы с декларацией (номера контейнеров, массы) |
| R2 | Код ТН ВЭД не в списке ручного контроля |
| R3 | Стоимость за кг в правдоподобном диапазоне |
| R4 | Отправитель в списке доверенных участников |
| R5 | Страна происхождения в списке разрешённых |

### 3.3. Модель

Качество прогноза на отложенной выборке. Разделение по времени: обучение на прошлом, проверка на будущем.

| Показатель | Значение |
|---|---|
| MAE модели | ≈1,5 ч |
| MAE простой оценки по медиане | ≈5,0 ч |
| ROC AUC срыва стыковки | ≈0,90 |
| Выборки | 576 записей на обучение, 144 на проверку |
| Версия модели | `gbm-v4` |

### 3.4. Сводка

Сводный дашборд по коридору:

- объёмы за 4 или 13 недель (переключатель «4 нед.» / «13 нед.»);
- доля видов транспорта;
- задержки;
- суммарный CO₂е;
- последние перевозки.

### 3.5. Доступ — роли и токены

Окно **«Доступ»**: поля «Токен брокера» и «Токен проверяющего».

| Роль | Может | Токен по умолчанию |
|---|---|---|
| Брокер (логист) | Менять сценарии, выбирать маршруты, сохранять и отправлять декларации | `dev-broker-token` |
| Проверяющий (инспектор) | Принимать решение по декларации на рассмотрении | `dev-reviewer-token` |

- Встроенные токены разработки работают только для запросов с этого же компьютера.
- Токены, введённые в окне, хранятся только в текущей вкладке браузера.
- Свои токены задаются через `.env` (см. раздел 5).

## 4. Управление контейнерами

| Задача | Команда |
|---|---|
| Запустить (после первой сборки) | `docker compose up -d` |
| Пересобрать после изменения кода | `docker compose up -d --build` |
| Посмотреть статус | `docker compose ps` |
| Логи приложения | `docker compose logs -f app` |
| Остановить, **сохранив** данные | `docker compose down` |
| Остановить и **стереть** данные (чистый старт) | `docker compose down -v` |
| Проверить, что API живо | `curl -s http://127.0.0.1:5173/api/health` |

`/api/health` возвращает `"status":"ok"` и `"graph_backend":"neo4j"`. Если там `"networkx"`, Neo4j недоступна, и маршруты считаются резервным способом.

**Сброс перед показом.** Если вы уже одобряли декларации или выбирали маршруты, верните всё к исходному состоянию:

```bash
docker compose down -v && docker compose up -d
```

**Проверка отказоустойчивости реестра:**

```bash
docker compose stop witness-2
```

Сохраните черновик декларации ещё раз. Запись по-прежнему заверена (2 из 3), а у «Порт» стоит «недоступен».

```bash
docker compose stop witness-3
```

Теперь кворум не достигнут, и система показывает, что запись не заверена.

```bash
docker compose start witness-2 witness-3
```

Узлы вернутся. Пропущенные записи они не подписывают задним числом и отмечаются как «отстаёт». Для полностью чистого состояния — `docker compose down -v`.

## 5. Настройки (`.env`)

Создайте файл `.env` рядом с `docker-compose.yml`. Образец лежит в `.env.example`. Все переменные необязательны.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `WEATHER_PROVIDER` | `open-meteo` | `synthetic` — встроенная погода, для полностью повторяемых цифр без интернета |
| `BROKER_TOKEN` / `REVIEWER_TOKEN` | `dev-broker-token` / `dev-reviewer-token` | Свои токены ролей |
| `DISABLE_DEFAULT_TOKENS` | выкл. | `1` — отключить встроенные токены разработки |
| `ENABLE_API_DOCS` | выкл. | `1` — включить документацию API по `/docs` |
| `GRAPH_DB_URL` | `bolt://graph:7687` | Пустое значение — работать без Neo4j (networkx) |
| `GRAPH_DB_PASSWORD` | `caspian-graph-local` | Пароль Neo4j |
| `LEDGER_WITNESS_KEYS` | dev-ключи | Ключи узлов реестра в формате `witness-1=…,witness-2=…,witness-3=…` |
| `AUDIT_HMAC_KEY` | dev-ключ | Ключ подписи журнала аудита |

После изменения `.env` выполните `docker compose up -d`.

## 6. Запуск без Docker (для разработки)

Нужны Python 3.12 и Node.js 22. Сначала остановите Docker-версию (`docker compose down`), чтобы освободить порт 5173.

```bash
./scripts/dev.sh
```

- Скрипт сам создаст `.venv`, установит зависимости, поднимет API на `127.0.0.1:8000` и интерфейс на http://127.0.0.1:5173.
- Neo4j и сетевые узлы реестра в этом режиме не нужны: маршруты считает networkx, узлы реестра работают внутри процесса.
- Остановка — `Ctrl+C`.

**Тесты и сборка фронтенда:**

```bash
./scripts/check.sh
```

**Сквозная проверка сценария жюри** против запущенного сайта (95 проверок):

```bash
.venv/bin/python scripts/demo.py --base-url http://127.0.0.1:5173
```

Скрипт меняет данные: одобряет декларации и переключает сценарии. После него сделайте `docker compose down -v && docker compose up -d`.

## 7. API для интеграций

Все запросы, кроме `/api/health`, требуют заголовок `Authorization: Bearer <токен>`.

```bash
curl -s -H "Authorization: Bearer dev-broker-token" http://127.0.0.1:5173/api/dashboard
```

| Запрос | Что возвращает или делает |
|---|---|
| `GET /api/dashboard` | Все перевозки с прогнозом, погодой, маршрутами |
| `GET /api/shipments/{id}` | Цифровой двойник одной перевозки |
| `POST /api/shipments/{id}/scenario` | Сценарий, тело `{"kind":"storm"\|"congestion"\|"closure"}` |
| `POST /api/shipments/{id}/scenario/reset` | Сброс сценария |
| `POST /api/shipments/{id}/route` | Выбор альтернативного маршрута |
| `GET /api/hubs/forecast?shipment_id=SCT-001` | Загрузка хабов на 72 ч и узкие места |
| `GET/PUT /api/shipments/{id}/preclearance` | Получить или сохранить черновик декларации |
| `POST …/preclearance/validate`, `…/submit`, `…/review` | Проверка, отправка, решение проверяющего |
| `GET /api/shipments/{id}/audit/verify` | Проверка целостности журнала |
| `GET /api/shipments/{id}/ledger` | Статус узлов реестра и кворума |
| `GET /api/model/metrics` | Метрики модели |
| `GET /api/summary?weeks=4` | Сводка по коридору |

Полное описание полей — в `README.md` (таблица API) и `docs/CONTRACTS.md`.

## 8. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `no configuration file provided: not found` | Команда запущена не из папки проекта. Сделайте `cd hackathon-cicada` |
| `permission denied … docker.sock` | Нет прав на Docker: `sudo usermod -aG docker $USER` и перелогиниться |
| `port is already allocated` / сайт не открывается | Порт 5173 занят. Остановите другой процесс или поменяйте порт в `docker-compose.yml` (`"127.0.0.1:5174:5173"`) |
| `app` долго в `health: starting` | Ждёт Neo4j (до минуты при первом старте). Смотрите `docker compose logs -f graph app` |
| Погода подписана «резервные данные» | Нет доступа к Open-Meteo. Всё работает; или задайте `WEATHER_PROVIDER=synthetic` |
| В источнике маршрутов «networkx» вместо Neo4j | Neo4j не поднялась: `docker compose restart graph`. Функциональность та же |
| `401` в интерфейсе | Окно «Доступ» → вписать `dev-broker-token` / `dev-reviewer-token` → «Сохранить» |
| `403` при «Принять» | Решение принимает только проверяющий; брокер свою декларацию принять не может |
| Декларация уже «Принята», нечего показывать | `docker compose down -v && docker compose up -d` |
| Не хватает памяти | Neo4j занимает до 1,25 ГБ. Закройте лишние программы или запустите проект без Docker (раздел 6): там Neo4j не нужна |
