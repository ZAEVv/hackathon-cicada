# Проверки прототипа

## Выполнено

- `./scripts/check.sh`: **106 тестов прошли**, TypeScript и Vite production build успешны.
- `scripts/demo.py`: финальный сценарий жюри — шесть перевозок → шторм и узкое место
  Махачкалы в прогнозе узлов на 72 ч → закрытие и альтернатива через Амирабад → выбор
  маршрута (деталь, дашборд, сводка, прогноз узлов) → сброс и матрица сценариев →
  предоформление: авто-путь `auto_accepted` (SCT-001) и ручной путь `needs_revision` →
  новая версия → `demo_accepted` (SCT-004), идемпотентный повтор, проверка журнала на
  каждом шаге → сводка 4/13 нед. → метрики модели. Проверяет отношения, а не точные
  числа; PASS/FAIL по каждой проверке, код выхода ≠ 0 при ошибке.
- Chromium/Playwright, 1440×1000: сценарий, выбор маршрута, сброс, редактирование
  документов, отклонённая проверка, исправление, отправка, принятие в демо,
  проверка цепочки и экран качества модели. Ошибок JavaScript не обнаружено.
- Chromium, 390×844: горизонтального переполнения страницы не обнаружено.

Есть одно предупреждение библиотеки Starlette об устаревании интеграции TestClient
с httpx; на результат тестов не влияет.

## Исправления интеграционного ревью

1. Выбор исходного допустимого маршрута сохраняется при повторном GET.
2. Задержка документов больше не меняет задним числом исходное расписание:
   прогноз задерживается, пропущенная стыковка остаётся видна.
3. Хронология обновляет прогнозы после сценария и выбора маршрута; план и факт
   сохраняются отдельно.
4. Недоступную альтернативу нельзя выбрать в интерфейсе; сервер также проверяет
   допустимость при каждом выборе.
5. Вероятностная оценка модели отделена от обнаруженного срыва расписания.
6. Время до дедлайна в ML приведено к единому смыслу: запас для переменных задержек
   после базового прибытия и обработки. Равенство дедлайну допустимо.
7. Устаревшие ответы при переключении груза не заменяют данные нового груза.
8. Несохранённые изменения документов блокируют проверку и отправку в интерфейсе.
